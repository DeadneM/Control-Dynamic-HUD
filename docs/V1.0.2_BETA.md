## Objective and changes

One coherent beta build addresses exactly these two options:

1. Rearm the existing navigation injection on every menu ready callback, inside
   the same first-Page::bind window. Do not move execution before visual/base
   setup (the earlier Y experiment broke the background). The JavaScript wrapper
   retries after an unavailable engine, detects a replacement engine.on, and does
   not stack wrappers on the same function. Selection tests use explicit true/1
   state attributes and separate class tokens; `unselected`/`inactive` do not match.
2. Retain LaunchIndicator+0x19 but publish changed values through the game's own
   model serializer and the fingerprint-checked public View notification at slot
   69. The old code only wrote the field after the game's updater had notified
   Coherent. The new path sends one notification per value change and restores
   the saved original field during F1 before hiding it again at expiry. The
   serializer is resolved from an exact unique masked publication signature;
   verify its prologue and executable-text bounds, otherwise fail open.

No new detour or executable patch is added. Keep split MultiLaunch icon/outline,
center-dot mask, action guards, Mission Select model patch, HUD lifecycle,
hotkeys and 1.0.1 runtime fixes. Public defaults remain HideNewGame=0,
HideMissionSelect=0, ShowDiagnostics=0. Package stays README + plugins/DLL + INI.

at 0x608ED4: serializer call at 0x608EE6 resolves to 0x609600, followed by a
public View virtual call at +0x228. The same publication tail is unique in DX11
at 0x608E74 (serializer 0x6095A0). Reflection metadata identifies the relevant
LaunchIndicator bool at +0x19 (MultiLaunch +0x41 is a different field).
The installed Coherent public vtable 0x270780 slot 69 points to RVA 0x82980.
Notification is allowed only with the established supported Coherent fingerprint
and exact public vtable/slot match. Native model memory changes are not treated
as visual proof.
