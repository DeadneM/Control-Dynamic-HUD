## Exact local evidence

Read-only splash.ui inspection shows the splash-text / MENU_PRESS_TO_START display;
it does not register an OnSelect action to progress the native state. SendAnyKey
is only a key-capture registration for bindings/credits, not a title-progress
action. Do not invent a Coherent event or send repeated generic Select inputs.

The native ProgramFlowClientStateSplashScreen tick has a phase-0 input wait.
On PC it also accepts its +0x24 flag, clears that flag at the ordinary input
join, then executes the existing user/profile checks. The option sets this same
one-shot flag before calling the original tick, instead of sending a Windows key
or changing a loading/save slot.

Primary RTTI identities are checked for ProgramFlowClientStateSplashScreen and
UISplashScreen. Slot 1 tick and slot 4 exit are located from that unique primary
state vtable; no new executable detour/trampoline is used. Before changing the
two data slots, verify tick/phase/advance patterns, platform-global reference,
ready flag store, primary splash page identity and the exact Page::unloadPage
import used by exit. Unknown/modified layouts fail open to the manual prompt.

Audited installed executables:

| Item (RVA) | DX11 | DX12 |
| --- | --- | --- |
| Splash flow primary vtable | 0xE4B250 | 0xE4B268 |
| Splash flow tick | 0x543F60 | 0x543F60 |
| Splash flow exit | 0x544700 | 0x544700 |

The implementation resolves identities/byte patterns rather than hard-code these
RVAs. It also requires the established supported Coherent fingerprint/public
View ABI. The flow tick consumes only the state pointer in the audited code.

## Runtime boundaries

When SkipPressAnyKey=0 no additional lookup or splash hook is installed.
When enabled, the hook requires the native waiting phase, the same initial state
object, no existing native progression flag, PC platform mode, the exact splash
page, its native ready flag and supported public View. Start the configured delay
only after readiness. Missing readiness expires after 30 seconds; losing a ready
page, phase change or a different object cancels it. The native exit hook consumes
the attempt even after manual progression, including state-address reuse on a
later title return. The process latch is set before requesting progression.
Do not dereference the state after the original tick, which may destroy it.

No startup movie skip, profile selection override, consent acceptance, save-file
access or system keyboard event. Profile/consent/DLC requirements can still need
manual interaction; the existing AutoContinue gates remain unchanged. Title skip
does not synthesize the keyboard/controller input that cancels AutoContinue.

Menu cleanup, navigation/background repair, guards, HUD, Mission Log, F1,
CrosshairDot, Launch/fade and split icon/outline code are retained. Public
HideNewGame, HideMissionSelect and ShowDiagnostics remain 0. Package stays DLL/INI.
